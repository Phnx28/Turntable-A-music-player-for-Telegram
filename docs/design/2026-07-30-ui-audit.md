# Telegram Turntable — UI audit

Date: 2026-07-30
Method: app served locally, all API responses stubbed with representative data (6 sources of
mixed kinds, 48 tracks, long titles, a source with a sync error, a pinned source, synced
lyrics, real audio) so every surface rendered through its own code path. Every view, tab,
dialog and empty/error state was driven and screenshotted at 1440 / 1120 / 860 / 760 / 390 /
320 px in both themes. Claims below are marked **confirmed** where they were verified by
computed styles, geometry probes or the source, and **unverified** where they were not.

Findings that turned out to be artifacts of the stub (`undefined cached`,
`Counting undefined/10`, `candidates.map is not a function`) are excluded, except where the
surrounding handling is itself a defect (see B8, D4). Two suspicions were tested and
retracted: the dark-mode logo swap (A11) and dialog Escape handling, which works everywhere.
Baseline screenshots of every surface described here are in `docs/design/baseline/`, and the
code they were taken from is tagged `pre-redesign-2026-07-30`.

## A. Broken — functional

### A1. On a phone, opening Now Playing makes playback unreachable — **confirmed**
At 390×844, `#now-panel` is `position: fixed; inset: 0; z-index: 25`; `#player` is
`z-index: 10`. `document.elementFromPoint()` at the play button's centre returns
`SECTION#now-panel`, and the button is not hittable. The panel contains no transport
controls at all — only close, the three tabs, and the lyrics/metadata editors.

So: tap the artwork → you cannot pause, skip, seek, or see progress. You have to find the
small × to regain control. This is the most-used screen on mobile.

`style.css:872-886` sets the fullscreen panel; `now-content` gets `padding-bottom: 84px`
so *lyrics* clear the player, but the player itself stays covered.

### A2. The Queue tab contradicts itself three ways at once — **confirmed**
With a track playing and nothing queued after it, the pane simultaneously shows:
- header: "Your queue is empty"
- a rendered row: "PLAYING / Angels / Burial"
- below it: "Your queue is clear." + "Browse library"

Mechanism:
- `app.js:1089` — the summary counts only `upcoming` (items after `queueIndex`), so the
  currently-playing item doesn't count as queue content.
- `app.js:1099` — the empty-state block is **concatenated after** `rows` rather than
  replacing them: `rows + (upcoming.length ? "" : '<div class="queue-empty">…')`.

Also two words for one idea ("empty" / "clear"), and Clear stays enabled.

### A3. The collapsing Now Playing header can never fire — **confirmed**
`app.js:1376`:
```js
const scrollable = content.scrollHeight - content.clientHeight - header.offsetHeight;
if (top > 48 && scrollable > 48) setNowHeaderCompact(header, true);
```
Measured at 1440×900 with synced lyrics loaded: `scrollHeight 636`, `clientHeight 206`,
`header.offsetHeight 546` → `scrollable = -116`. The guard needs `> 48`, so it is never
satisfied. The header is a **sibling** of `#now-content`, so its height is not part of that
element's scroll extent and should not be subtracted at all.

Consequence: the header stays 546px of an 812px panel (**67%**), leaving 206px for content.
The comment at `style.css:522-526` describes this exact problem as solved ("expanded it ate
61-68% of the viewport… collapsed it is ~170px, so content roughly triples"). It isn't.

Fix: drop `- header.offsetHeight`.

### A4. Per-source track counts are never visible on desktop — **confirmed**
`.source-count` lives inside `.source-actions`, which is `position: absolute; opacity: 0`
(`style.css:963-973`). On hover the wrapper becomes visible — but `style.css:977` then sets
`.source-link:hover .source-count { display: none }`. Probed at rest: count text `"412"`,
`display: block`, wrapper `opacity: 0`.

Net effect: the number exists in the DOM and is unreachable in every state. Meanwhile
"All music 811" and "Liked songs 27" above it *do* show counts, so the column reads as
broken rather than absent. On coarse pointers `style.css:1243` hides it permanently too.

### A5. The hover overlay makes the row you are pointing at unreadable — **confirmed**
`.source-actions` is an absolutely-positioned box with `background: var(--surface)`. On
hover it paints an opaque panel over the right side of the row, clipping the title
mid-word — observed as "Hyperdul", "ambient d…", "Nyege Nyeg⌐" across three different
states. On the *active* row the white box also sits on the accent tint, so a hard-edged
white rectangle appears inside a blue band.

The comment at `style.css:959-962` explains why the actions were moved out of the grid
(they were squeezing titles). The overlay solves the reflow and reintroduces the occlusion.

### A6. The collapsed rail grows a horizontal scrollbar from a 1px overflow — **confirmed**
`style.css:1001` sets `.sidebar-collapsed .source-link { width: 46px }`. The rail column is
68px with `padding-inline: 11px` → 46px of content box, minus 1px taken by the vertical
scrollbar → `nav.clientWidth = 45`, `nav.scrollWidth = 46`. Chromium renders a horizontal
scrollbar *with arrow buttons*, which appears as a stray `◀ ● ▶` control floating in the
rail.

Fix: `width: 100%` / `max-width: 46px`, or `width: auto; margin-inline: auto`.

### A7. Every button in the metadata dialog is 55% too tall — **confirmed**
Two rules collide:
- `style.css:790` `.metadata-form label { display: grid; gap: 8px }` — specificity (0,1,1)
- `style.css:1172` `.inline-choice { display: inline-flex; align-items: center }` — (0,1,0)

The type-and-class selector wins, so the "Cover" label stacks its text above the select
instead of sitting beside it, making that block 62px tall. `.form-actions`
(`style.css:791`) is a flex row with `align-items: normal` (= stretch), so Save changes /
Reset to Telegram / Fetch metadata all stretch from `min-height: 40px` to **62px**.
Measured: `inlineChoiceDisplay: "grid"`, all three buttons 62px.

This is the specificity collision pattern to watch for: `.metadata-form label` and
`.inline-choice` cancel each other out.

Fix: scope as `.metadata-form .inline-choice` (or `:where()` the label rule) and add
`align-items: center` to `.form-actions`.

### A8. A failed metadata lookup leaves a skeleton shimmering forever — **confirmed**
`fetchMetadata()` sets `#candidate-section.hidden = false` and fills `#candidate-list` with
a skeleton, then `catch (error) { $("metadata-status").textContent = error.message }`. The
catch never clears the list or re-hides the section. On any failure — and MusicBrainz
rate-limits aggressively — the user sees a loading animation and an error message at the
same time, indefinitely.

### A9. You cannot filter a playlist on a phone — **confirmed**
`style.css:871` — `.library-heading .small-copy, .search-control { display: none }` below
860px. The per-playlist filter is simply gone. Global search remains, but it searches all
of Telegram rather than the open playlist, so the narrowing task has no mobile equivalent.

The same rule drops the track count while the decorative `CHANNEL` eyebrow is kept.

### A10. Zero-result states keep their furniture
With a filter that matches nothing: the `TRACK / SOURCE / TIME` header row stays above an
empty list, and Play / Shuffle remain enabled and primary-black. Play on "0 tracks" has
nothing to do.

### A11. ~~The dark logo breaks in Firefox~~ — **retracted, not a defect**
`style.css:341` swaps the mark with `content: url("/assets/logo-dark.png")` on an `<img>`.
I suspected Firefox would ignore this, since `content` on replaced elements was long
non-standard. Tested directly in both engines: Chromium and Firefox both apply it (computed
`content` resolves and the element adopts the replacement image's intrinsic size). No change
needed. Recorded here because the technique looks fragile and someone will want to "fix" it.

## B. Accessibility and legibility — measured

### B1. The focus ring is 1.38:1 — **confirmed by computation**
`--focus-ring` uses `color-mix(in srgb, var(--accent) 70%, transparent)`. Composited over
`--paper`: `#c0d5f8`, relative luminance 0.6575 vs paper 0.9281 → **1.38:1**. WCAG 2.2
SC 1.4.11 requires 3:1 for a focus indicator. This is the primary keyboard affordance in
the entire app.

It also degenerates: focusing the *current* track row puts an accent ring inside an accent
tint, so the indicator vanishes into the state it is marking.

Fix: outer ring `--ink`, keep accent as the inner halo.

### B2. Progress communicates nothing at rest — **confirmed by computation**
`style.css:716` builds the track as a gradient: elapsed `--accent`, buffered
`color-mix(accent 38%, --line)`, remaining `--line`.
- elapsed vs remaining: L 0.5608 vs 0.6689 → **1.18:1**
- elapsed vs buffered: 0.5608 vs 0.6236 → **1.11:1**

The thumb is `opacity: 0` until hover/focus (`style.css:719-722`). So at rest the most-watched
element in a music player has no visible position, no visible fill, and no distinction
between played and buffered. (In dark mode the same tokens work — the failure is
light-mode-only, which is its own inconsistency.)

### B3. Accent as a foreground colour is 1.72:1
`.icon-button.active { color: var(--accent) }` (`style.css:729`) — used for liked tracks and
pinned sources. `#a8c7fa` on `#f7f7f4` is 1.72:1. The like state survives only because
`app.js:910` also swaps outline → filled heart; the colour carries nothing. Good redundancy,
bad colour.

### B4. Nine type sizes below 11px
8px: `.global-result-mark`, `.queue-state`, `.cache-state`, `#repeat-badge`.
9px: `.global-search-signal small`, `.global-result-group h3`.
10px: `.global-result small`, `.source-count`, `.volume-pct`, `.eyebrow`/`.utility`.
The queue is the worst region: 8 / 10 / 12px stacked.

### B5. The one success colour is untokenised and fails AA
`.cache-state.ready { color: #3b8753 }` (`style.css:1097`) — the only green in the app, not
a token, no dark-mode variant. On `--surface` in dark (#141516) it computes to **4.17:1**,
below the 4.5:1 needed for text — at 8px.

### B6. All Settings help text is semibold — **confirmed**
`style.css:1170` sets `.setting-block label span { color: var(--muted); font-size: 12px }`
but no `font-weight`, so it inherits `600` from the global `label` rule (`style.css:182`).
Probed: `font-weight: 600`. Every explanation renders at the same weight as its own label —
visibly so on "MusicBrainz does not use an API key for lookups…", which reads louder than
"MusicBrainz contact" above it.

### B7. Native scrollbars everywhere, none styled
Up to four unstyled scrollbars can be on screen at once (rail `nav`, library, `now-content`,
modal). They overlap content: the settings scrollbar sits on the segmented control's right
edge, the discover scrollbar next to the checkbox column, the `now-content` scrollbar on the
lyric text.

### B8. Raw exception text reaches users
- Playback failure → "The element has no supported sources." (the `HTMLMediaElement` string)
- Metadata failure → whatever `error.message` holds, including client-side `TypeError`s

Both paths funnel `error.message` straight into UI copy with no distinction between a
server-authored, user-actionable message and an internal exception. The error dialog's
title is also generic ("Couldn't complete that") and `#error-retry` stayed hidden for a
playback failure, which is inherently retryable.

## C. Identity and the token system

### C1. One accent doing eight jobs
`--accent: #a8c7fa` currently signals: active source, current track, focus ring, active tab
underline, primary-button hover, mode-button on-state, toast timer, login stripe, skeleton
shimmer, combo-box active option. When one colour means everything it means nothing — and
this particular periwinkle reads as a framework default rather than a choice. Telegram's own
blue is `#2AABEE`; nothing in the palette references the subject.

### C2. Two visual languages for "this is the current one"
- background tint: `.track-row.current`, `.source-link.active`
- left accent bar: `.queue-row.current` (`style.css:1087`),
  `.sidebar-collapsed .source-link.active` (1002), `.restart-notice`

`style.css:491` states the rule explicitly — "Background only… no left bar anywhere" — and
three rules break it.

### C3. Inter is never loaded
`--font-ui: Inter, Avenir, "Segoe UI", ui-sans-serif, system-ui, sans-serif` with no
`@font-face` and no preload anywhere. On any machine without Inter installed, the face
carrying the whole identity silently becomes Segoe UI or a generic sans. Either ship it or
design for the fallback.

### C4. The type scale is a gap and a cluster
44px display, 28px modal h2, 20px, then ten sizes packed into 8–15px. One confident move at
the top, nothing answering it, and a pile of near-identical small sizes below.

### C5. Six hardcoded colours outside the tokens
`#f7f7f4` (`.qr-code`, duplicates `--paper`), `rgb(17 17 17 / .82)`
(`.track-play-overlay` — duplicates light-mode `--ink`, wants to be a `--scrim` token),
`#3b8753`, `#111214` and `#1a1b1d` (`.qr-stage`, `.qr-inset`), and `#14161a`
(`.combo-option.is-active`, where `--accent-ink` was clearly intended).

### C6. Dark mode flattens the spatial model
`--paper` and the rail are both `#0e0f10`, divided by a 1px `#2c2e30` line, so the sidebar
stops reading as a separate plane (in light mode rail `#f7f7f4` vs rows hovering to `#fff`
does read). And `color-mix(accent 30%, transparent)` over near-black loses almost all
chroma, so the current row reads as *greyed out* rather than *playing* — the opposite
emphasis to light mode.

## D. Information architecture

### D1. `source.kind` reaches the UI as a raw enum, rendered three ways
- sidebar: `channel` / `private` / `saved` / `bot` — lowercase database values
  (`app.js:552` prints `source.kind` verbatim)
- discover dialog: `CHANNEL · 412 MUSIC FILES` — mono uppercase
- library header eyebrow: uppercased by CSS

No shared formatter, and no human labels ("Private chat", "Saved Messages", "Bot").
`bot · needs attention` is the sync-error state, which reads like a category.

### D2. Two track counts that can disagree
The sidebar's "All music" total is `state.sources.reduce(… + item.trackCount)` (`app.js:542`),
derived from a cached `_track_counts` map. The header's "N tracks" is `state.totalTracks`
from the live query. Different sources of truth for the same number, on screen together.

### D3. The library's sort order is invisible and unchangeable
Tracks come back `ORDER BY t.sent_at DESC, t.rowid DESC` (`core.py`). The date posted is
never displayed anywhere in the UI, never labelled, and there is no sort control for the
track list at all — while a `TRACK / SOURCE / TIME` header row sits above it looking
sortable. For a library assembled from channel posts, "when was this posted" is arguably the
most useful axis, and it is the one axis the UI hides.

### D4. The Details tab omits most of the details
Renders Source, Album, Album artist, Genre, Year, File, Size (`app.js:913`). Missing, though
all indexed and available: duration, date posted (`sentAt`), track number, disc number
(both editable in the metadata dialog but never shown), mime type. The action buttons also
sit below the fold behind the 546px header (see A3).

### D5. The Source column repeats the page title on every row
Inside a single source, the widest data column (`minmax(130px, .75fr)`, ~210px) prints the
same string as the h1, once per row. It is correctly hidden below 1120px — it should also be
hidden whenever a specific source is selected.

Inverted elsewhere: the rail truncates "Bandcamp Weekly Ri…" at 232px while the track list
prints "Bandcamp Weekly Rips & Radio Sessions" in full.

### D6. One 8px column carries four unrelated meanings
`.global-result-mark` renders: `"Open"` or `"Preview"` for sources, and a formatted duration
*or* the word `"Telegram"` for tracks (`app.js:796,799`). Provenance and duration in the same
slot, at 8px.

### D7. Layout starves the title first
- 1120px with the panel open: h1 truncates to **"Hyper…"** (an 8-character source name), and
  the library gets 492 of 1120px — 50% of the screen is chrome. The summary wraps to two
  lines because of the raw timestamp.
- 320px: titles truncate to ~11 chars ("Rival Deal…", "Sines (ta…") and subtitles too
  ("Kode9 & Th…"), while duration + like + menu keep a fixed 120px of a 294px content width.

### D8. Search results are a second, weaker row system
Global search rows have no artwork at 52px while library rows have 43px covers at 68px;
titles are 13px vs 14px; there is no result count and no indication the list is capped.
Same objects, two treatments, and recognition is weakest exactly where it matters most.

### D9. Discover mixes taxonomies and states a falsehood while loading
Sections run `SELECTED` (a state) then `CHANNELS` / `BOTS` (types). Uncounted sources show
`0 MUSIC FILES` rather than "—" or "counting…", so a source that hasn't been scanned looks
identical to an empty one. Checkboxes sit at the far right of a ~700px row, a long way from
the name. The dialog scrolls as a whole (`.modal { overflow-y: auto }`, no sticky header), so
scrolling a long chat list takes the Sort / Filter / type controls off screen.

### D10. Modes overlap in the rail
In bulk-select mode the per-row hover actions (sync / full rescan / pin) still appear and
still occlude the title, so you can pin while selecting. "All music" and "Liked songs" sit in
the same list without checkboxes and at a different indent, so they read as missing theirs.
Adding the bulk bar shifts the layout and introduces a scrollbar.

### D11. Unlabelled duplicate affordances
Sync appears twice with the same glyph at different scopes (header `#sync-source`, rail
`#sync-all-sources`). Per-source rows offer "sync new" (`#i-sync`) and "full rescan"
(`#i-repeat`) side by side, unlabelled, at 27px — and a loop glyph reads as *repeat*, not
*rescan*. The pin marker before a title renders as a 12px pale-blue tick that looks like a
text artifact.

## E. Copy

1. `LIBRARY LENS` (global search) and `LOCAL METADATA LAYER` (metadata dialog) are
   implementation language. Nobody has a lens.
2. Every one of the ten panels carries an eyebrow; several restate the heading —
   `PLAYER PREFERENCES / Settings`, `NO MATCHES / Nothing matches "qqqqq".`,
   `NOW PLAYING` above a panel already labelled Now playing. Keep the ones that classify
   (`CHANNEL` over `Hyperdub`, `SAVED LOCALLY` over `Liked songs` — that one does real work);
   cut the rest.
3. Bulk **"Unselect"** actually removes sources from the library
   (`POST /api/sources/bulk-select` with `false`). It reads as "clear my checkboxes".
   Should be "Remove from library".
4. `synced 7/30/2025, 2:30:00 AM` — a raw `toLocaleString()` with seconds, which wraps the
   summary to two lines at 1120px.
5. `5 matching contacts` before anything has been typed. `Saved Messages / Telegram contact`
   — it is your own cloud storage, not a contact, and the same destination also exists as a
   separate player button. `41 cached` has no noun.
6. Settings → Network shows `Started without run.py, so this setting is not applied. Restart
   with: uv run python run.py` — a shell command in an end-user preference pane.
7. Empty states: "No matches yet." (the *yet* implies more is coming, and there is no
   recovery action). Headlines carry terminal punctuation — "Add a channel, bot, or private
   chat." — which reads like a sentence fragment rather than a title.
8. Network's help text explains only the safe option; "Anyone on my network" — the choice
   with an actual exposure consequence — gets no warning.

## F. What is good and should survive the redesign

- **`vector-effect: non-scaling-stroke` on icon strokes** (`style.css:121-126`) — a real
  problem (Ionicons' 32-unit stroke on a 512 viewBox rendering 0.75px at 12px and 1.62px at
  26px), correctly diagnosed, with the reasoning written down.
- **`prefers-reduced-motion` honoured in 11 places**, including `scrollIntoView` behaviour
  and the library reveal — genuinely rare.
- **Share has undo-with-delay**: `pendingShare` holds a timer and surfaces an "Undo" toast,
  so an irreversible outward action is recoverable. Exactly right.
- **The Account danger zone**: tinted box, red rule, red heading, bordered destructive
  button, and copy that states the consequence precisely. Make this the pattern for
  "Remove password" too.
- **"Who can reach this player"** — a system setting named by what the person controls.
- **The filter-no-match empty state** — names the query, suggests a narrower action, points
  at the alternative tool, offers a way out. The best-written state in the app.
- **Liked state carried by glyph fill**, not colour alone.
- **The mobile breakpoint reasoning** — comments explain why shuffle/repeat are dropped but
  skip is not, and why the utilities column is `auto`. Design decisions with recorded
  rationale.
- Mono with `tabular-nums` for durations.
